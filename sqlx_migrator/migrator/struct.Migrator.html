pub fn new(dialect: Dialect<DB>) -> Self

Creates a migrator configured by dialect. Migrator::default uses Dialect::postgres, Dialect::mysql or Dialect::sqlite; pass an adjusted one to change its lock, DDL behaviour, table prefix or schema, for example no lock behind a transaction pooling proxy such as PgBouncer.

§Example
use sqlx_migrator::{Dialect, Migrator};
let dialect = Dialect::sqlite_with(Some("v1"), None).unwrap();
let migrator = Migrator::<sqlx::Sqlite>::new(dialect);
assert_eq!(migrator.table_name(), "_v1_sqlx_migrator_migrations");

pub fn add_hook( &mut self, hook_type: HookType, function: impl for<'a> Fn(&'a mut <DB as Database>::Connection, &'a HookContext<'a, DB>) -> HookFuture<'a> + Send + Sync + 'static, )

Adds a function which runs at the point of a run given by hook_type, see HookType. The function gets the connection doing the work and a HookContext. Functions of the same type run in the order they were added, and one which fails stops the run.

The function returns a boxed future so it can borrow the connection, which a plain fn or a closure does by wrapping its body in Box::pin(async move { .. }).

pub fn table_name(&self) -> String

Get name of table which is used for storing migrations related information in database

Format depends on the prefix and schema of the dialect:

  • With schema: {schema}._sqlx_migrator_migrations
  • With prefix: _{prefix}_sqlx_migrator_migrations
  • With both: {schema}._{prefix}_sqlx_migrator_migrations
  • Default: _sqlx_migrator_migrations
§Examples
use sqlx_migrator::{Dialect, Migrator};
let dialect = Dialect::sqlite_with(Some("v1"), Some("app_schema")).unwrap();
let migrator = Migrator::<sqlx::Sqlite>::new(dialect);
assert_eq!(
    migrator.table_name(),
    "app_schema._v1_sqlx_migrator_migrations"
);

pub fn generate_migration_plan( &self, plan: Option<&Plan>, applied_migration_sql_rows: &[AppliedMigrationSqlRow], ) -> Result<Vec<&'_ Box<dyn Migration<DB>>>, Error>

Generate migration plan using pre-fetched applied migration rows.

This is the core plan-generation logic that performs no database access. It is useful when you have already called Migrator::fetch_applied_migration_from_db (e.g., to display status alongside the plan) and want to avoid a redundant database round-trip.

If plan is None, returns all migrations in apply order. If plan is Some, processes the plan using the supplied applied_migration_sql_rows.

§Errors

Returns an error if the migration list is empty, contains unresolved virtual migrations, has a dependency deadlock, or if the plan references an app/migration that does not exist.

pub fn status<'get>( &self, applied_migration_sql_rows: &'get [AppliedMigrationSqlRow], ) -> Result<Vec<(&'_ Box<dyn Migration<DB>>, Option<&'get AppliedMigrationSqlRow>)>, Error>

Generate migration status using pre-fetched applied migration rows.

This is the core status logic which performs no database access. It is useful when you have already called Migrator::fetch_applied_migration_from_db for another purpose and want to avoid a redundant database round-trip. Returns every migration in apply order paired with a reference to its applied migration row when applied, or an empty list when no migrations are added.

§Errors

pub async fn prune( &self, connection: &mut <DB as Database>::Connection, ) -> Result<usize, Error>

Prune the migration table by deleting applied migration entries which no longer have a corresponding migration in the migration list.

This is useful for cleaning up the migration table after migrations are removed from the codebase, since such entries would otherwise linger in the migration table forever. Returns the number of pruned entries.

§Errors

If fetching or deleting applied migrations fails

pub async fn repair( &self, connection: &mut <DB as Database>::Connection, ) -> Result<usize, Error>

Removes the migrations which started running and never finished from the migration table, so they run again. Returns the number of removed entries.

Only the migration table is changed: the operations of a failed migration ran partly, so the database has to be fixed by hand first.

§Errors

If fetching or deleting failed migrations fails

pub async fn sync<O>( &self, connection: &mut <DB as Database>::Connection, old_migrator: &O, ) -> Result<(), Error>
where O: OldMigrator<DB>,

Records the migrations an old migrator reports as applied, skipping ones this migrator does not know or which are already recorded. Applied times are not preserved. Use it to move from another migration system or to rename the migration table.

§Errors

If sync cannot be completed

Run provided plan migrations

Returns a RunReport listing every migration which was applied or reverted along with the time each one took. Progress is emitted as tracing events at info level inside a span per run and per migration.
