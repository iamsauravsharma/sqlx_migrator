Module hook 

Source
Expand description

Hooks run functions at fixed points of a run

Register a function with Migrator::add_hook and the HookType saying when it runs. It gets the connection doing the work, which is the transaction of an atomic migration, so a hook can set transaction scoped options such as Postgres SET LOCAL lock_timeout. When the lock strategy holds the whole plan in one transaction every hook runs inside it. A hook which fails stops the run and rolls back the transaction it ran in.

Migration hooks are not called for a fake plan since it executes nothing.

§Example

Give up on a lock held by another session after five seconds instead of waiting for ever

use sqlx::{Executor as _, Postgres};
use sqlx_migrator::hook::{HookContext, HookFuture, HookType};
use sqlx_migrator::Migrator;

fn lock_timeout<'a>(
    connection: &'a mut sqlx::PgConnection,
    _context: &'a HookContext<'a, Postgres>,
) -> HookFuture<'a> {
    Box::pin(async move {
        connection.execute("SET LOCAL lock_timeout = '5s'").await?;
        Ok(())
    })
}

let mut migrator = Migrator::<Postgres>::default();
migrator.add_hook(HookType::BeforeMigration, lock_timeout);
// a closure works the same way
migrator.add_hook(HookType::AfterRun, |_connection, context| {
    Box::pin(async move {
        println!("ran {} migrations", context.report().map_or(0, |report| report.len()));
        Ok(())
    })
});
