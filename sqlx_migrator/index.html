Crate sqlx_migrator 

Source
Expand description

Library to create sqlx migration using rust code instead of sql.

The guide below walks through Operation, Migration and Migrator. See the hook, cli and sync modules for hooks, the command line and moving from another migration tool.

§Usage

Define an Operation (the up / down work) and group operations into a Migration:

ⓘ
use sqlx_migrator::error::Error;
use sqlx_migrator::migration::Migration;
use sqlx_migrator::operation::Operation;

struct CreateSample;

#[async_trait::async_trait]
impl Operation<sqlx::Postgres> for CreateSample {
    async fn up(&self, connection: &mut sqlx::PgConnection) -> Result<(), Error> {
        sqlx::query("CREATE TABLE sample (id INTEGER PRIMARY KEY)")
            .execute(connection)
            .await?;
        Ok(())
    }

    async fn down(&self, connection: &mut sqlx::PgConnection) -> Result<(), Error> {
        sqlx::query("DROP TABLE sample").execute(connection).await?;
        Ok(())
    }
}

struct FirstMigration;

impl Migration<sqlx::Postgres> for FirstMigration {
    fn app(&self) -> &str {
        "main"
    }

    fn name(&self) -> &str {
        "first_migration"
    }

    // `app` + `name` must be unique. Parents run first; a `(app, name)` tuple
    // can stand in for a parent you cannot import.
    fn parents(&self) -> Vec<Box<dyn Migration<sqlx::Postgres>>> {
        vec![]
    }

    fn operations(&self) -> Vec<Box<dyn Operation<sqlx::Postgres>>> {
        vec![Box::new(CreateSample)]
    }
}

§Shortcuts

A (up, down) pair of strings is a reversible operation, one string an irreversible one, include_sql! embeds .up.sql / .down.sql files and operation::from_fn builds an operation from closures. The migration! macros cover the simple case; implement the trait by hand for replaces, run_before or is_atomic.

ⓘ
sqlx_migrator::postgres_migration!(
    FirstMigration,
    "main",
    "first_migration",
    sqlx_migrator::vec_box![],
    sqlx_migrator::vec_box![
        (
            "CREATE TABLE sample (id INTEGER PRIMARY KEY)",
            "DROP TABLE sample"
        ),
        "INSERT INTO sample (id) VALUES (1)",
        sqlx_migrator::include_sql!("sql/0001"),
    ]
);

§Running

ⓘ
use sqlx_migrator::migrator::{Migrator, Plan};

let mut migrator = Migrator::default();
migrator.add_migration(Box::new(FirstMigration)).unwrap();

let report = migrator.run(&mut *conn, &Plan::apply_all()).await.unwrap();
migrator.run(&mut *conn, &Plan::revert_all()).await.unwrap();

Plan can also target an app, a migration or a count.

Each app must end in one head, a migration nothing else in the app comes after. Two migrations written side by side make two heads, and run fails with Error::MultipleHeads until one depends on the other (see Migrator::heads). Progress is logged with tracing.
